# RuTool Linux 2.1.1: перенос, сборка и проверки

Проверки выполнены 24 ноября 2026 года в ветке `port/linux-2.1.1`.
После сборки пользователь подтвердил успешную ручную проверку и разрешил
публикацию исходников и AppImage. Автоматические проверки перечислены ниже.

## Исходники и сохранение предыдущей версии

- Основа Linux-порта: `a5b9d310c4747c56789d9741e6564cdd88929f09`.
- Оригинальная база: `060f097`; её `client-v2/` совпадает с тегом `v2.0.8`.
- Целевой тег: `v2.1.1`, коммит `61f92f0820484e6bf9fb8347a0e671a48120a1b7`.
- Сравнение оригиналов: 26 файлов, +2390/−1764 строки; значительная часть
  объёма связана с переводом CRLF в LF. Анализ выполнялся также с
  `git diff --ignore-space-at-eol 060f097 v2.1.1 -- client-v2/`.
- Изменения переносились по файлам с трёхсторонним слиянием относительно базы.
  Новый заголовок QML адаптирован вручную с сохранением Linux-кнопок.
  Каталог `client-v2/` целиком не заменялся.
- Старые каталоги сборки и три AppImage 2.0.8 сохранены. Проверка их собственных
  `SHA256SUMS` в `dist-appimage/`, `dist-appimage-ui/`, `dist-appimage-ui2/` прошла.
- На этапе переноса и сборки команды, изменяющие `.git`, не выполнялись.

## Что изменилось в upstream 2.1.1

| Область | Изменения поведения |
| --- | --- |
| Обновления приложения | Канал API сменился на `api/installer/application/v2/latest` и `/v2/candidate`; заменён `config/update-public.der` |
| Premium API | В каталоге появился необязательный объект `LoadingScreens` с размером и SHA-256; разрешён адрес `/api/installer/premium/addons/loading-screens` |
| Авторизация дополнения | Загрузка с Bearer-кодом, повторная серверная проверка Premium непосредственно перед записью; перенаправления Premium-загрузки запрещены существующим механизмом |
| Формат дополнения | `RUTD1` (`.rudp`): copy/literal записи с little-endian длинами и смещениями; вход и выход ограничены 64 MiB, длина результата должна совпасть с оригиналом |
| Установка дополнения | Отдельная замена конкретного loading-screens bundle; фиксированные исходный/целевой SHA-256 и размер, сохранение оригинала и транзакционный rollback |
| Восстановление | Общая проверка журнала выделена в `recoverFiles`: поддерживаются прежние одна/три цели перевода и отдельная цель дополнения |
| Контроллер | Отдельное состояние `addonWork_`; ошибка дополнения не портит состояние выбранного `.rut`, ошибки журналируются как `Addon` |
| Интерфейс | Новый главный экран, настройки папки/пакета/темы/восстановления, боковой каталог, карточка дополнения, обновлённые панели дисклеймера и отчёта, размытие фона |
| Инструменты | Новый `scripts/build-addon-delta.py` для создания дельт с контрольными суммами; существующий файл вывода не перезаписывается |
| CMake и зависимости | Версия 2.1.1, новая диагностическая сцена settings; версии Qt 6.8, Mbed TLS 3.6.7 и zlib 1.3.2 прежние; QML теперь явно использует QtQuick.Effects и Layouts |

Криптографический код PortableCrypto, подписи `.rut`, контейнер RUT111,
расшифровка и структура обычных пакетов не менялись. Новый `.rudp` не является
пакетом `.rut`: безопасность дополнения опирается на HTTPS/Premium-проверку,
хеш скачивания и зафиксированные в коде хеши исходного и конечного bundle.

## Что перенесено и сохранено на Linux

Все перечисленные общие изменения перенесены. Сохранены:

- `src/platform/linux/`, платформенные интерфейсы и регистр символов в путях;
- `openat`/`O_NOFOLLOW`, POSIX-блокировки, безопасная замена и проверка процессов;
- обработка ситуации, когда `rename` уже выполнен, а `fsync` каталога вернул ошибку:
  заменённый файл включается в rollback;
- Steam/Proton discovery и канонизация найденных путей;
- PortableCrypto, проверки подписей, Linux AES-GCM/RULOC1 и права локального ключа;
- встроенный `installer-keys.json`, XDG override и отказ при неверном override;
- Linux-кнопка обновления форка и ссылка сопровождающего в Credits;
- сборка AppImage на существующем SDK Ubuntu 24.04 / GCC 14 / Qt 6.8.3.

В новом заголовке показаны версия и Linux-кнопки. Символ информации заменён на
обычный `i` на Linux: символ `ⓘ` не отображался в доступном шрифте контейнера.

Дополнение использует тот же безопасный механизм транзакционной замены, что и
основной перевод. Путь `Preload/Windows/…bundle` — имя ресурса игры,
используемого также через Proton, а не вызов Windows API.

## Что остаётся Windows-only

Windows launcher, DLL payload, `RuToolUpdater.exe`, подготовка плана обновления
и запуск обновлятора остаются под платформенными условиями. На Linux
`checkApplicationUpdate()` ничего не запускает, а запрос обновления сообщает
о ручной замене AppImage. Windows-кнопка обновления скрыта.

Правки upstream для длинных Win32-путей (`\\?\` и UNC), версия в PowerShell
сценариях и новый канал обновлений сохранены в Windows-ветке кода. Они не
компилируются в Linux-сборку; работоспособность Windows здесь не проверялась.

## Сборка и регрессионные тесты

Использован существующий образ `rutool-linux-bootstrap` и SDK из
`build-linux-sdk/`. Внутри контейнера выполнены существующие сценарии:

```sh
./scripts/build-linux.sh build-linux-2.1.1-tests
./scripts/build-linux.sh build-appimage-2.1.1 -DBUILD_TESTING=OFF
./scripts/fetch-appimage-tools.sh build-linux-tools
RUTOOL_TOOLS_DIR=/work/build-linux-tools \
  ./scripts/package-appimage.sh build-appimage-2.1.1 dist-appimage-2.1.1
```

Компиляция, CTest и упаковка выполнены с `--network none`. Исходники, SDK и
синтетический `machine-id` были смонтированы в контейнер; каталог настоящей
игры и пользовательские настройки не монтировались.

Обе сборки — Release, C++23, GCC 14.2.0, с `-Wall -Wextra -Wpedantic
-Wconversion -Wsign-conversion -Werror`. В окончательной сборке предупреждений
компилятора нет. Строгие флаги не ослаблялись. Промежуточные ошибки нового
UI-теста исправлены в самом тесте: преобразования внутри макроса QtTest,
изолированное сохранение согласия и поиск делегатов Repeater в визуальном дереве.

## Ручные проверки и ограничения

Настоящая Blue Archive не запускалась и не изменялась. На своей стороне проверь:

1. Обычный запуск AppImage на целевом Linux/Steam Deck, FUSE или `appimage-run`
   на NixOS, масштабирование и аппаратный рендеринг. Здесь Wayland проверен
   только с программным рендерингом; настоящий X11-дисплей не проверялся.
2. Поиск твоей игры и миграцию существующих настроек/кода бусти из 2.0.8.
3. Живой публичный и Premium-каталог, действующий/просроченный код, скачивание,
   отмену и повторную попытку при реальном сетевом обрыве.
4. Установку подходящего подписанного `.rut`, повторную установку и восстановление
   оригиналов. Автотесты проверяли синтетические пакеты и файлы.
5. Premium-дополнение на поддерживаемом оригинальном bundle: успешную установку,
   повторное распознавание установленного дополнения и отказ на другой версии.
   Настоящий bundle и серверный Premium-код для этой проверки не использовались;
   успешная установка реального дополнения не заявляется проверенной.

Оригинал дополнения сохраняется отдельно в
`${XDG_DATA_HOME:-$HOME/.local/share}/RuToolInstaller/Backups/Addons/loading-screens/`.
Как в upstream 2.1.1, отдельного UI восстановления дополнения нет; кнопка
«Восстановить файлы» относится к основному переводу. Не считай её удалением
экранов загрузки. Сохраняй `private/local.key` вместе с резервными данными.
